0.6.2

  • The version now matches the Scalactive library (0.6.2).
  • Names imported by name in <script> (import org.scalajs.dom.File) are no longer counted as uses of the generated wildcard imports, and a package the script already imports with * is not imported again, so -Wunused:imports no longer warns about import org.scalajs.dom.* in the generated code.

0.6.1

  • The version now matches the Scalactive library (0.6.1).
  • Component tags starting with an uppercase letter (<Link>, <Input>, ...) are no longer treated as HTML void elements, so they can have children and closing tags.
  • A .st component named like a built-in one (RouterLink, Route, ...) is used instead of the built-in one in the same package.
  • The generated code imports only what it uses, so -Wunused:imports no longer warns about it.

0.6.0

  • The version now matches the Scalactive library (0.6.0). This version needs Scalactive 0.6.0 or later; a warning is shown when the project uses an older library, since errors in .st files may be wrong.
  • The language server compiles templates the same way as the library: expressions that read reactive values (.v) in {{ }}, bindings, v-if, v-for and child component props are tracked. Props of type Reactive accept value expressions such as :count="s.n.v * 2" without false type errors.

0.4.4+1

  • Ctrl/Cmd+Click on the definition of a Scala name in the script jumps to its usages, including those in the template (a list is shown when there are several).

0.4.4

  • The version now matches the Scalactive library (0.4.4), which compiles <style lang="scss"> to CSS.
  • <style lang="scss"> / lang="sass" are handled as SCSS / Sass with the Sass plugin (completion and inspections), and Comment with Line Comment uses // in SCSS. SCSS is highlighted with the bundled TextMate grammar.
  • The language server reads CSS classes in SCSS and Sass styles too (nested rules, &-suffix, // comments), for class completion, go to definition and unused-class hints.

0.4.1

  • First release on JetBrains Marketplace.
  • Syntax highlighting for .st files (Scala in the script and template expressions, CSS in the style).
  • HTML features in the template (completion, closing tags, Emmet) and CSS features in the style.
  • Language injection for strings after // language=xxx comments in the script.
  • Completion, type errors, hover, go to definition (including library sources), auto-import, inlay hints, rename of props and formatting by the Scalactive language server.
  • New → Scalactive Component, Open Generated Scala Source, and renaming of component tags with the file.
